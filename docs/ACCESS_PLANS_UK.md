# Trial, місячна підписка та доступ

Редакція: 24.11.2026. Онлайн-оплату ще не підключено. Після міграції тарифні
обмеження вимкнені, доки адміністратор явно не запустить їх.

## Модель

- Trial: один раз при реєстрації, стандартно 7 днів безкоштовно, без картки.
- Pro: один повний набір функцій. Планується разова оплата місяця без
  автоматичного списання. На 3/12 місяців додамо пізніше.
- На `/plans` тільки Trial (за замовчуванням 7 днів) і Pro за $3/місяць. Обидва плани відкривають весь користувацький функціонал; онлайн-оплата ще не підключена.
  Справжньої купівлі, платіжного webhook і фінансових листів ще немає.
- Після завершення доступу логін, відновлення пароля, профіль, сторінка
  підписки та звернення до адміністратора залишаються доступними.
- Власні збережені карти, прогнози, консультації, історія та нотатки можна
  читати. Експорт збережених консультацій і видалення власних даних дозволені.
  Нові розрахунки й редагування потребують активного доступу.

## Строки та права

`access_grants` містить незалежні видачі Trial/Pro, джерело, причину, початок,
кінець, відкликання та створення. Ні архів, ні видачі при expiry не видаляються.
Активність: `revokedAt == null && startsAt <= now && now < endsAt`.
Визначальним є час API. Pro пріоритетніший за Trial; `endsAt` — максимальний
кінець активних видач поточного плану. Після Pro може лишитися чинний Trial.
Відкликання одного запису не скасовує інші. Cron для завершення не потрібний.

`FREE` лишається технічним значенням для відсутності видач; в інтерфейсі це
«Без активної підписки», не безкоштовний тариф. ADMIN обходить тарифні
обмеження; Pro ніколи не дає адміністративних прав.

Trial створюється в транзакції реєстрації:
`endsAt = startsAt + trialDays * 86400000`. Повторний логін не запускає його
заново. Нова тривалість впливає лише на наступні реєстрації. Адмін може
вручну продовжити доступ. Захист від створення різних акаунтів для повторного
Trial ще не реалізований; це не завершена антифрод-система.

## Безпечний запуск

`access_settings`:
- `trialEnabled=true`, `trialDays=7` (допустимо 1–365);
- `enforcementEnabled=false`;
- `transitionDays=14` (1–365);
- `launchedAt` — перший запуск; `revision` — захист конкурентного редагування.

Перший запуск enforcement у Serializable-транзакції видає всім наявним
неадміністративним користувачам Pro з `source=transition` на `transitionDays`
від моменту запуску. Чинні довші видачі не скорочуються. Налаштування, видачі
та аудит атомарні. Повторне перемикання не створює нових перехідних видач,
бо `launchedAt` збережено. В UI після запуску перехідна тривалість незмінна.

Не вмикати обмеження до підключення способу оплати/продовження та попередження
користувачів. У preview розрахунки працюють як до міграції. Банер показує
бета-статус, строк доступу або режим читання. Статус оновлюється при переходах,
поверненні у вікно та щохвилини. Сервер перевіряє право на кожну нову операцію.

## API та архів

### Повідомлення користувачам

Після успішної реєстрації користувач переходить на `/plans?welcome=1`:
бачить фактичний план і кінцеву дату з API, перелік можливостей, відсутність
автосписань, умови збереження архіву та кнопку переходу до роботи. Початковий
внутрішній маршрут `next` збережено; зовнішні адреси не приймаються. Звичайний
логін не показує цей вступ повторно. Відкриття welcome не запускає новий Trial.

Банер у робочій зоні показує строк у днях/годинах, точну кінцеву дату за Києвом
із підписом часового поясу та посилання на умови. За 48 годин до завершення
з'являється контрастне попередження. Відлік округлюється до години вгору;
точна дата залишається видимою. Trial показується також у preview, але з явним
поясненням, що завершення зараз не блокує роботу. Email-нагадування цим етапом
не додаються. Відлік є інформативним; права визначає API.

Робочі маршрути у власному Fastify-контексті з `preHandler`: карти, прогнози,
інтерпретації, астроподії, збереження/перерахунок карт, консультації, шаблони,
спостереження та профілі налаштувань. POST/PUT/PATCH при enforcement потребують
Trial/Pro або ADMIN. Відповідь: 403 `SUBSCRIPTION_REQUIRED`, `plansUrl=/plans`;
без авторизації — 401. Перевірка відбувається перед обчисленням або зміною.

GET/HEAD, OPTIONS та DELETE не блокуються підпискою; перевірки власності й
авторизації лишаються чинними. POST-збіги спостережень — виняток для перегляду
архівної карти, без нового астрологічного розрахунку. Публічні/доступні за
посиланням карти зберігають чинну видимість. Підписка не відкриває чужі
приватні дані. Консультації після завершення доступу відображаються для читання,
без автозбереження; локальну чернетку можна завантажити окремо.

Trial/Pro відкриває бібліотеку опублікованих спостережень інших авторів.
При enforcement старий `sharedKnowledgeUntil` не замінює загальну підписку;
у preview він зберігається для акаунтів без Trial/Pro. Публікація, прийняття
редакцій і захист приватних нотаток не змінюються.

## Адмінка

- `GET/PUT /admin/access/settings`: trial, перехідний строк, запуск обмежень.
- `GET /admin/access/users/:id`: поточний доступ та останні 100 видач.
- `POST /admin/access/users/:id/grants`: видача до конкретної дати.
- `POST /admin/access/users/:id/grants/:grantId/revoke`: відкликання.

Увімкнення має підтвердження в UI. Причина видачі/відкликання обов'язкова.
Дата вводиться за Києвом, надсилається в UTC. Видача починається зараз;
продовження — новий запис із заданим кінцем, не автоматичне додавання місяця.
Роль повторно перевіряється в транзакції; `admin.access.*` містить автора,
дату, зміни й причину. Для припинення доступу відкликати всі активні записи,
включно з перехідним. Вимкнення enforcement тимчасово відкриває роботу всім.

## Розгортання та перевірки

Потрібна міграція `20261122000000_access_enforcement` перед новим API та
генерація Prisma Client під час збірки. Паролі, архіви та чинні строки не
перезаписуються; додаються поля налаштувань із безпечними початковими значеннями.

Додані тести політики/guard: preview, active/expired, анонімний запит, читання
архіву, межі строків та ADMIN. Тести, збірка, міграції, Docker і браузерні
перевірки не запускалися на прохання користувача. Перед enforcement потрібні
інтеграційні перевірки, конкурентний запуск, expiry, Safari та мобільні екрани.

Далі: платіжний сервіс, ідемпотентний webhook, облік платежів/повернень,
правило календарного місяця й продовження активного строку, листи про оплату
та завершення. Наразі цих платіжних механізмів немає.
