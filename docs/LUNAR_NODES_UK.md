# Тип місячних вузлів

## Вибір і сумісність

У формі розрахунку на дешборді та в робочій зоні (налаштування карти,
редактор профілю розрахунку) є поле «Місячні вузли»:

- Істинний вузол: Swiss Ephemeris `SE_TRUE_NODE`.
- Середній вузол: Swiss Ephemeris `SE_MEAN_NODE`.

Параметр зберігається як `calculationRules.lunarNodeType`: `true` або `mean`.
Відсутнє значення означає `true`, як у попередніх версіях. Це додаткове поле
контракту v1; значення наявних правил не змінені. Невідомі значення відхиляються.
Нові результати явно записують тип у налаштування. Міграція БД не потрібна:
профілі та розрахункові знімки вже зберігають правила в JSON.

Для порівняння з наданим прикладом Альтаїра треба явно вибрати «Середній вузол».
На відкритій карті застосувати профіль/правила, заново розрахувати прогноз
і за потреби зберегти новий результат. Раніше збережений прогноз самостійно
не перераховується. Збереження особистого профілю та призначення його основним
дозволяє використовувати середній вузол для наступних карт.

## Розрахунок

Північний вузол розраховується функцією `calc` для вибраного ідентифікатора
на відповідний момент ефемеридного часу. Південний вузол:

`longitudeSouth = (longitudeNorth + 180°) mod 360°`.

Швидкість обох вузлів однакова. Для натальної цілі береться натальний вузол,
для рухомої точки — позиція вибраного типу на транзитну/прогресивну дату.
Тип передається у вибірку положень, уточнення екзактів, календар прогресій
та його пошук входу в орбіс. Немає глобального перемикача, який міг би
змінити наступний розрахунок іншого користувача.

Соляр/лунар успадковують тип із наталу. У синастрії кожна карта використовує
власні правила. Правила виключення вузлів зі зв'язків домів та Південного
вузла з повільних прогресій залишаються незмінними.

Орбіси, метод прогресивних домів і часовий ключ не змінені. Заміна типу
вузла змінює його довготу й швидкість, а не вручну додає/віднімає дні.
