# Тимчасовий публічний доступ без домену

Cloudflare Quick Tunnel надає випадкову HTTPS-адресу `*.trycloudflare.com`.
Акаунт Cloudflare, власний домен і зміна DNS у тестувальників не потрібні.
Це тестовий режим без гарантій доступності, не заміна постійного домену.
Обмеження: до 200 одночасних запитів, без SSE; новий запуск створює нову адресу.
Документація: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

## Перед запуском

Застосунок уже має бути розгорнутий і працювати. Фронтенд має бути зібраний
з `NEXT_PUBLIC_API_URL=/api`, як у VPS workflow. Використовуйте лише тестові
дані: незалежні бекапи мають бути налаштовані перед роботою з даними клієнтів.
Публічна адреса не є паролем: будь-хто, хто її знає, може відкрити сторінку
входу й зареєструватися. Авторизація застосунку залишається, IP-фільтра на
тестовому вході немає. Не використовуйте тестовий пароль `admin`.

## Запуск на VPS

Спочатку закомітьте й відправте файли цієї зміни у Git із локального комп'ютера.
На сервері:

```bash
sudo git -C /opt/astro pull --ff-only
cd /opt/astro/deploy/vps
sudo bash test-tunnel.sh start
```

Перша команда завантажує конфігурацію. Скрипт завантажує два службових образи,
піднімає окремий внутрішній Caddy і тунель, отримує тимчасову адресу,
налаштовує CORS API саме для цієї адреси й коротко перезапускає API.
Очікування healthcheck API є частиною запуску, а не набором тестів.
Збірка застосунку, міграції, зміна паролів і видалення даних не виконуються.
Повний `deploy.sh` для цього запускати не потрібно.

Адреса виводиться як `Test URL: https://....trycloudflare.com`.
Відкрийте її, перевірте вхід, розрахунок і збереження тестової карти перед
надсиланням іншим. Вихід із SSH не зупиняє контейнери.

## Маршрутизація

Браузер -> Cloudflare HTTPS -> вихідний тунель VPS -> внутрішній Caddy.
Шлях `/api/*` направляється до API з видаленням префікса `/api`, інші шляхи
до фронтенду. Нові порти сервера не публікуються. PostgreSQL залишається
у внутрішній мережі. Основний Caddy, його сертифікати та IP-фільтр не змінюються.
API тимчасово дозволяє один новий Origin замість основного домену.

## Вимкнення та перезапуск

```bash
cd /opt/astro/deploy/vps
sudo bash test-tunnel.sh stop
```

Команда закриває тунель і відновлює CORS із основного `SITE_HOST`, перезапускаючи
лише API. Не використовуйте `docker compose down -v`: це може видалити дані.

Контейнери тунелю навмисно не перезапускаються автоматично: нова адреса
потребує оновлення CORS. Після перезавантаження VPS або збою тунелю знову
запустіть `start` і надішліть нове посилання. Не перезапускайте окремо
`test-tunnel`. Перед звичайним деплоєм застосунку виконайте `stop`.

## Діагностика на сервері

```bash
sudo docker compose --env-file .env -f compose.yaml -f compose.tunnel.yaml logs --tail=80 test-tunnel test-gateway
sudo docker compose --env-file .env -f compose.yaml ps -a
```

Логи показують підключення тунелю й помилки маршрутизації; статус контейнерів
допомагає відрізнити збій тунелю від проблеми API. Не публікуйте `.env`.
